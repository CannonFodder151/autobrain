# PostgreSQL 17 + pgvector Upgrade

## Current state

All three tiers (Demo, Default, Hosted) run **PostgreSQL 17** with the
**pgvector** extension pre-installed:

```yaml
image: pgvector/pgvector:pg17@sha256:cf134a767f474095eeba57e0117be8e568e011a63f33fbf252f14c9b760f8e6f
```

- **Major bump:** pg16 → pg17 (AUT-1749).
- **Digest pin** so the multi-arch manifest (amd64 dev box + arm64 Oracle VM) is
  immutable across every endpoint. Bump deliberately: verify release notes first.
- The `vector` extension is created by migration `g7h8i9j0k1l2`; the image ships
  the extension files so `CREATE EXTENSION vector` succeeds at migration time.
- In dev the port is published to `127.0.0.1:5432` only. In prod/hosted it is
  internal to the compose network.

## pgvector schema in use

Five tables carry `embedding vector(1536)` columns (dimension from
`EMBEDDING_DIMENSION`, matching `text-embedding-3-small`), each with an HNSW
cosine-similarity index:

| Table | Migration | Content embedded |
|-------|-----------|------------------|
| `diagnostics` | `g7h8i9j0k1l2` | Symptoms + AI response summary |
| `service_records` | `g7h8i9j0k1l2` | Description + notes + steps |
| `modifications` | `g7h8i9j0k1l2` | Name + notes + category |
| `receipts` | `g7h8i9j0k1l2` | Vendor + extracted line-item names |
| `social_issue_posts` | `u1v2w3x4y5z6` | Title + body (Issues Blog, AUT-627) |

`h1i2j3k4l5m6` rebuilt the indexes as **HNSW** (they were IVFFlat on older DBs,
which needs list tuning that does not pay off on small per-user tables).

The `embedding` columns exist at the **database layer only** — the SQLAlchemy
models do not map them. Writes go through raw SQL in
`backend/app/services/search.py` (`backfill_entity_embedding`).

**Alembic head:** single head at `m3rge06`, verified by
`backend/tests/test_alembic_heads.py`. Migrations run inside the backend
container on boot (`alembic upgrade head` in dev/prod, `python -m
app.db.bootstrap` in hosted), so a redeploy is a complete upgrade — no separate
migration step.

## Embeddings

Generated by 9Router's OpenAI-compatible `POST /v1/embeddings`
(`text-embedding-3-small`, 1536-dim). On the hosted stack the router does not
resolve the bare alias, so `EMBEDDING_MODEL` is set to the full OpenRouter id
`openrouter/openai/text-embedding-3-small` (AUT-2091).

If 9Router is unreachable, embedding generation is skipped and search falls back
to keyword-only ILIKE — the search endpoint never breaks.

## Upgrade procedure (pg16 → pg17, or any future major bump)

A PostgreSQL major-version bump needs a dump/restore, not a plain redeploy.
`pg_dumpall` from pg16 is **not** directly restorable into pg17 — use
`pg_dump`/`pg_restore` with the custom format and the `pg_upgrade`-free path:

1. **Freeze writes.** Put the backend into maintenance (scale to 0 or set
   `SELF_SIGNUP_ENABLED=false` + stop the Celery worker) so no new rows land
   mid-dump.
2. **Dump.** On the source host:
   ```bash
   docker exec <postgres_container> pg_dump -U "$POSTGRES_USER" -Fc autobrain > autobrain-$(date +%F).dump
   ```
3. **Ship the dump** to the target host (`scp`).
4. **Pull the new image** and update the compose digest for all three compose
   files (`docker-compose.yml`, `docker-compose.prod.yml`,
   `docker-compose.hosted.yml`) — the pin is duplicated in each.
5. **Restore** into a fresh empty `postgres-data` volume:
   ```bash
   docker run --rm -v <target_postgres_data>:/var/lib/postgresql/data \
     -e POSTGRES_USER=... -e POSTGRES_DB=... pgvector/pgvector:pg17@sha256:... \
     sh -c 'initdb -U "$POSTGRES_USER" "$POSTGRES_DB" && pg_ctl -D /var/lib/postgresql/data start -w'
   docker cp autobrain-*.dump <container>:/tmp/
   docker exec <container> pg_restore -U "$POSTGRES_USER" -d autobrain --clean --if-exists /tmp/autobrain-*.dump
   ```
6. **Verify the extension is present:**
   ```sql
   SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';
   ```
   If missing, `CREATE EXTENSION IF NOT EXISTS vector;` then re-run the vector
   migrations.
7. **Re-index.** HNSW indexes are not restored transactionally with the data in
   every pg17 path — re-run them if query plans regress:
   ```sql
   REINDEX INDEX diagnostics_embedding_idx;  -- repeat for the other four
   ```
8. **Start the app** so Alembic applies any head, then verify:
   ```sql
   SELECT count(*) FROM diagnostics WHERE embedding IS NOT NULL;
   ```
9. **Promote** in the mandated order (Demo → Default → Hosted, per AUT-107) with
   health checks between each tier.

## Pitfalls

- **Never edit prod data by hand** — DB changes go through Alembic revisions.
- The `pgvector/pgvector:pg17` digest differs per arch manifest list; the
  manifest-list digest (`sha256:cf134a76…`) resolves to the right image on both
  amd64 and arm64. Pinning a child manifest digest (as the frontend once did)
  breaks cross-arch deploys.
- `read_only: true` + `tmpfs: /tmp, /var/run/postgresql` in the prod compose —
  the data dir is the only writable path. A pg17 initdb that tries to write
  elsewhere fails with "read-only file system".
- Postgres 17 removes `vacuum_defer_cleanup_age`; nothing in the schema uses it.
- The Oracle VM's snap `dockerd` masks `/opt` and `/srv` as read-only core24
  squashfs — bind mounts must live under `/data` (AUT-1853).
